BLACKBOX — LOCAL PILOT ARCHITECTURE
Version 2.1 · Owner-approved local-first delivery. No production app has been implemented by this seed.

The current scope is specs/LOCAL-PILOT.md and delivery-profile.json: P0–P4, then handover and stop for feedback. Future hosting, SaaS, native clients and Passkeys are options, not automatic next milestones. Preserve a modular foundation without implementing their infrastructure now.

One local release contains React/Vite UI and landing page served by Fastify, a TypeScript API/auth/MCP layer and connector worker, a Rust business/query engine, PostgreSQL and local evidence storage. Compose/wrapper commands start it on the user's Mac. Only the authenticated web/API loopback port is exposed. Native packaging is not needed for the pilot. Document prerequisites and prove an actual Apple Silicon install, not just image compilation.

One automatic workspace/owner uses a CSPRNG-generated personal bearer login key. A normal browser session avoids repeated key entry. Authentication is not data encryption; a protected host-only reset replaces lost access without deleting business data. Read-only agents have distinct named keys/principals. Use maintained random/verifier/session components and a replaceable authentication boundary. Defer passkeys, employee invites, remote OAuth and fine-grained permission editors. See specs/IDENTITY-ACCESS-AND-RECOVERY.md for exact bootstrap/session/revocation/reset tests.

Keep tenant_id, composite references, validated service/RPC scope, real RLS and protected API/worker DB roles, tenant-aware in-memory keys and actual adversarial two-tenant fixtures. One visible local workspace is a UX choice, not permission to use global unscoped state. Credentials, identity and operational records are separate from the five business tracks. These boundaries make later deployment work possible; they do not certify SaaS readiness.

Sources, Facts, Commitments, Movements and Reservations are linked views over the canonical immutable journal. Runtime roles cannot update/delete/truncate committed journal payloads/links. Corrections/reversals append; mutable projections/jobs/auth are separate. Sensitive raw evidence has a distinct, explicit retention/redaction policy. Preserve exact money/quantity semantics and evidence lineage. A host administrator remains outside the application tamper-resistance boundary.

The write/read path is verified input -> durable PostgreSQL journal/outbox -> idempotent Rust reducer/projection/checkpoint -> consistent bounded RAM state -> authorized API/MCP answer. Do not independently dual-write RAM and PostgreSQL. The same Rust money/stock rules serve UI and MCP. Use direct scoped entity indexes, bounded queries and indexed cold history. Recovery loads a compatible snapshot/projection plus committed tail; corruption falls back to replay. Source freshness, durable commit and applied cursor are distinct. All 24 query contracts and broader history traversal remain required.

The first real adapters are Shopify/Shopify Payments, using supported outbound initial import, polling and reconciliation. Signed typed generic input, replay, bank CSV, policy and internal producers make full synthetic Order-to-Cash behavior reproducible. Provider authorization/account limits remain explicit. easybill/DHL and other cards stay planned; absence of their live data produces partial answers rather than fabricated invoices/shipments. No gateway/public callback or tunnel is required. Future provider ingestion still must honor retention/use requirements.

Default import is last 30 days plus disclosed accessible older open/related context, with fixed date choices, snapshots, ongoing collection and later expansion. A shared authorized service drives onboarding, Sources/details and every answer's readiness. Distinguish loaded/committed/query-ready counts, successful checks versus new events, requested versus verified history, and engine lag versus upstream gaps. Import/view/RAM/retention are independent choices.

Use maintained MCP SDK stdio through an authenticated local bridge sharing the query service. Agent keys permit workspace business/evidence reads, never owner administration or arbitrary SQL. Test a protocol client and record actual local-client compatibility separately. Public cloud agents do not gain access to loopback automatically; remote OAuth/routing is deferred.

Measure the 250k-entry smoke profile under actual declared Mac/container hardware, with realistic five-track data, concurrent ingestion, hot/cold reads, current authorization and bounded memory/recovery tests. Keep exact corpus and resources comparable between A/B builds. The 10m/100m contracts are preserved for later evaluation; do not claim those capacities without measurements or build HA solely for a future benchmark.

Implement specs/SYSTEM-AND-DIAGNOSTICS.md with a common sanitized structured log contract across wrapper/API/worker/Rust/MCP, persistent bounded local files and optional rebuildable search index. Use actual probes and shared source/readiness/cursor state for owner-only EN/DE health and filtered live/history views. Keep local CLI access during API/database/runtime outages, 15-minute debug expiry, seven-day/100-MiB-total technical retention and explicit bounded exports. Technical logs are separate from business journal and required durable security audit; do not put best-effort logging on the commit/query critical path or require a hosted observability stack. DIAG-01–08 are active pilot gates.

Dependency direction: domain <- application <- adapters/entrypoints. Keep TypeScript orchestration, Rust canonical rules, versioned cross-language schemas, source manifests/fixtures and shared question contracts separate. Use Drizzle/reviewed SQL, PostgreSQL-backed jobs, pnpm/Cargo lockfiles and pinned versions/licenses. No required Kafka/Redis/Kubernetes/vector DB/proprietary control plane. Add material ADRs, not a framework project.

P0 selects minimal contracts and starts implementation; P1 produces the local persisted slice; P2 proves business/query/UI/import/restart behavior; P3 connects local agents and initial real sources; P4 proves local install/backup/restore/upgrade/performance and hands over. Preserve current acceptance/evidence and the source work register. A restricted preview with blockers is not an unqualified pilot pass, and a verified local pilot is not a public SaaS certification. Both agents stop at this same scope for comparison.

All engineering content remains English. UI and landing page default to English with complete German localization, matching the unchanged visual reference. Deliver a short tester guide and explicit sanitized diagnostic export without automatic telemetry. Let observed feedback determine the next scope.
