# Local application and installation

The active delivery is LOCAL-PILOT.md and ../delivery-profile.json. The previous web/native/public-server design remains in future/WEB-DESKTOP-AND-DEPLOYMENT.md as deferred reference only.

Deliver a complete local browser application and landing page with the supplied visual language, English default and German localization. It talks to a persistent local backend. Setup automatically creates one owner/workspace and issues the personal access key specified in IDENTITY-ACCESS-AND-RECOVERY.md. Implement source setup/progress/health, journal/evidence/questions, named read-only agent access, exports, owner-only System & Diagnostics and local settings. No employee invitations, platform operator, workspace switcher or remote-backend selector is required.

Keep a versioned Compose backend with API/web, worker, Rust engine, PostgreSQL and persistent evidence storage. Implement `./blackbox doctor setup up down status logs demo verify backup restore upgrade` plus `diagnostics export` and a host-only `reset-access` command. Commands are not supplied by this seed. Document container-runtime and other prerequisites without silently installing them. Provide a tested Apple Silicon local install with pinned images/source-build fallback and exact start/stop/recovery instructions. Separate ports, credentials and volumes for concurrent A/B builds. Keep database/engine ports internal and the browser/API listener on loopback only.

Closing the browser does not stop backend ingestion. Explicit shutdown preserves journal, jobs, cursors and snapshots; restart resumes and exposes actual catch-up progress. No journal processing occurs while the machine/runtime is stopped. Normal startup must not reseed user data, rotate saved access keys or remove volumes. Show prerequisite/setup errors in understandable terms. A native app shell, signing/notarization and desktop runtime controls are deferred; do not block the pilot on them.

Source connectivity is `local_standalone`: outbound import/polling/reconciliation. No webhook callback is registered to localhost, and no public receiver/gateway or tunnel is required by the product. A provider's separate authorization/account prerequisites remain visible. Public MCP clients cannot reach a private endpoint automatically; offer the tested local client/bridge.

Back up database, evidence and required encryption material; rehearse isolated restore and a populated upgrade on the local release. Restore rotates stale login/agent access before reopening. Keep exactly one writer to a workspace. Remote migration, multi-host failover and shared-tenant hosting are future options requiring explicit scope and tests, not deliverables for this pilot.

LOCAL-05, LOCAL-06, LOCAL-08, OPS-01/02 and the active install/security gates define the required proof. A container image build is not a real-Mac installation result. Do not advertise a dependency-free native installer or a publicly deployable SaaS artifact.

Follow SYSTEM-AND-DIAGNOSTICS.md for the exact log/doctor/export CLI, pre-container setup logs, persistent host-visible files during API/database/runtime outages, owner-only UI and bounded storage/debug behavior. Prove DIAG-01–08 with the existing installation and recovery gates. The supplied prototype has no implemented diagnostics page; extend its visual language without treating mock screenshots as evidence.

## Landing-page download and first install

Owner-approved requirement after baseline-v12: a first-time visitor must be able to get the actual local installation package from the landing page. This is current pilot scope, not a later marketing task. The seed has no release package or working production download yet.

Provide a prominent **Download for Mac** / **Für Mac herunterladen** action in the hero and navigation, repeated in the closing call to action. All instances use the same release metadata. Keep a clearly separate demo action; downloading must not silently open a simulation or require Blackbox signup. Near the download, show the supported platform/architecture (initially macOS Apple Silicon), tested minimum OS/runtime requirements, release version/date, file format/size and a link to **Installation guide** / **Installationsanleitung**. Identify a preview as a preview. Windows, Intel Mac and Linux downloads appear only when actually built/tested; do not infer support from a user's browser or show placeholder links as available releases. A platform suggestion never hides manual platform information.

The landing page and installation guide must render without a running Blackbox backend, owner login, database or pre-existing local installation. Deliver a separately servable static landing build with configurable release URLs, and test it from a separate static host before first install. This permits later hosting on the chosen website without exposing the local API. Public deployment, a domain and a public release publication are not prerequisites for the pilot and are not authorized by this spec change. Use an authorized test/private distribution endpoint for pilot download proof; document any repository/account access it requires. A private GitHub release is not advertised as an anonymous public download. No private-repo token is embedded in browser code or URLs. A blocked distribution prerequisite is reported, not silently marked passed.

### Installable artifact and release metadata

Ship a versioned downloadable archive containing the wrapper, pinned Compose configuration, non-secret configuration examples and a quick-start guide. Its primary path uses the release's prebuilt images; a tester must not need to clone Git, install a Rust/Node toolchain or build the application to use the advertised download. Clearly explain the required container runtime, its supported versions and any image-registry access/network requirements before installation. Verify image accessibility for the same audience as the download. A source archive or CI artifact that only a developer can use is not the promised installation package. Keep a documented source-build fallback separate.

Native `.app`/DMG and signing/notarization remain deferred. Label the delivered archive and container requirement honestly; never imply a dependency-free native installer. Test the browser-downloaded archive on the actual supported Mac, including file permissions and applicable OS download/security prompts. Provide normal supported steps; do not instruct users to disable OS security globally. Never package credentials, runtime data or a preconfigured shared owner key.

Maintain one versioned release manifest consumed by the landing build. It records release status/version/date, tested commit, artifact filename, platform/architecture, format, byte size, SHA-256, download URL, installation-guide URL and prerequisite details. Keep manifests and asset names consistent with the same immutable tested version and pinned image references. Serve shared downloads over HTTPS (isolated localhost test hosting may use HTTP). Show a checksum and version-specific release notes. A checksum detects corruption; it is not a claim of signing/notarization. Validate metadata and artifact bytes in the release workflow, and promote a latest alias only after the versioned download/install checks pass.

Before an artifact exists or if release metadata is invalid, show an honest localized **Download not available yet** / **Download noch nicht verfügbar** state with demo/guide access; do not emit a fake active download or silently substitute another architecture/version. Handle failed requests with clear retry/help guidance. A correctly disabled preview button is useful during development but cannot satisfy the final working-download gate. Browser restrictions on download filenames/CORS must not break ordinary link navigation to the real artifact.
