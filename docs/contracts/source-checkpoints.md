# Protected provider pagination

Runtime `source_checkpoint: 2` and additive migration009 protect pagination positions independently of source credentials. Provider cursors are arbitrary opaque data that may encode identifiers or personal content. They are not anonymous and are not progress labels. The worker validates a bounded control checkpoint (UTC scope, recent/open stage, page count, required journal cursor), seals a nonempty provider cursor with the existing versioned AES-GCM secret envelope, and binds it to tenant, connection and job. Only the active source worker decrypts it for the exact provider request. Nested pagination positions stay in request memory until the complete logical object commits. The API and logs never receive them.

`source_jobs.checkpoint.after` is always null on disk. `sealed_after` carries authenticated ciphertext, with fresh nonce and the data-key version. The former duplicate `import_runs.cursor` is null. Database constraints reject plaintext writes. Final pages do not retain an unused end cursor; completing a job also removes any sealed cursor. Paused, failed and reauthorization jobs retain their encrypted resume position until resumed/completed or the installation is removed. This is operational secret state rather than original-document retention, and is not a claim of a 90-day cursor purge. Original documents use the separate evidence policy. Existing encrypted backup generations retain their own operational cutoff under the configured backup policy.

Claim and page advance run within the existing tenant transaction, lease and connection/credential fences. A failed decryption cannot cause an unscoped restart or accepted page. Backup/restore verify every stored cursor's authentication; data-key rotation rewrites and verifies it before retiring a live key. Cursor ciphertext cannot be swapped across jobs, connections or workspaces. No new cipher construction or external key service is introduced.

Migration009 never transfers a legacy plaintext cursor into the journal/audit. It discards both old stored copies, resets pagination count, invalidates outstanding leases, and records a safe `source.legacy_cursor_discarded` security event. Pending imports enumerate the same fixed from/through/stage again using existing observation deduplication. Completed jobs are not restarted. No retained business observations or import totals are deleted. Old backup formats5/6/7/8 remain checked against their exact known contracts before isolated forward restore; applying this migration does not prove the still-pending populated in-place upgrade workflow. Old runtime binaries reject the new contract.

Unit tests cover strict metadata, canary ciphertext, bound identities and tampering. Actual source/restart, backup/rotation and prior-release restore evidence is recorded separately after execution. This contract closes one field-inventory finding; the full inventory and provider authorization review remain separate work.
