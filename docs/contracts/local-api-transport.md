# Local API transport

The MCP stdio bridge uses `packages/transport/local-api.ts`. It accepts HTTP on loopback only; the named `api` Compose service is allowed only in an explicitly enabled synthetic fixture environment. It never follows redirects or accepts embedded credentials, query fragments or a non-root base. It emits the exact `127.0.0.1:<public-port>` Host authority, preserving the API's Host/Origin enforcement. A caller-supplied hostile Host cannot replace this authority. The independent negative HTTP test still verifies that the server denies a genuinely hostile Host.

Node 24's built-in fetch discarded the explicit Host override in the container fixture path. This caused truthful authorization failures despite committed journal/reducer state. Explicit Node HTTP sends the intended authority; no API allowlist exception is added. Native loopback endpoints default to their configured port; container fixture transport defaults to 18741, with the installation's PUBLIC_PORT override.

Requests are bounded to 2 MiB, responses to 4 MiB and the whole operation to five seconds (or earlier caller cancellation). Network/authentication/malformed response failures remain failures. MCP returns an unavailable error rather than inventing a business result. Redirect status is returned without credential forwarding. Tests exercise actual loopback sockets, authority, remote/credential rejection, oversized input/output, cancellation and non-followed redirects. The persisted slice separately exercises actual MCP framing/authentication, fixed cutoffs, tenant isolation and recovery.
