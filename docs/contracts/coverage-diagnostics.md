# Canonical coverage diagnostics

Coverage is a typed business assertion, not a place for notes. `packages/contracts/coverage-codes.ts` enumerates recognized canonical field paths and semantic gap codes for `missing_fields`, and four currently implemented provider limitation codes for `limitations`. Arrays retain their existing 100/20 item bounds. Field names include their dataset and nested property path; whole-dataset gaps remain supported. New diagnostics require an explicit registry/schema change, not caller-defined text matching a broad regular expression.

Both authenticated producer HTTP ingestion and internal worker/review ingestion validate this boundary before committing journal/evidence content. Names, email addresses, token-shaped text and even syntactically plausible lowercase prose are rejected with the generic `invalid_request` response. Actual original source content still belongs in encrypted evidence under its receipt-based retention policy. Numeric calculations, source coverage semantics and all 24 question fixtures remain unchanged.

This corrects the prior regex-only coverage-code acceptance. It does not inspect or rewrite older immutable journal rows. If personal content was previously embedded there, treat it as an explicit policy incident; ordinary journal UPDATE/DELETE remains prohibited. A recognizable code is a schema value, not proof that a producer's coverage assertion is true. Scope, time, identity and evidence checks still determine readiness.

Verification: `pnpm test`, `python3 scripts/verify-evidence-policy.py --output .runtime/evidence-policy.json`, and `python3 scripts/verify-questions.py --output .runtime/questions.json`. The first includes all positive/missing fixture parsing and adversarial canaries; the second exercises signed producer requests with PostgreSQL/filesystem inspection; the third checks actual persisted API/Rust/SDK MCP and recovery. Executing or listing a command is not a passing result. The complete field/provider inventory and legacy evidence-source association audit remain separate required work.
