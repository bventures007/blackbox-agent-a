# Shopify fulfillment assignments

The outbound Admin GraphQL 2026-10 adapter reads fixed-cutoff order selections, nested fulfillment-order groups and their complete line pages. It uses the shared protected credentials, account checks, leases, bounded retry, durable cursor and immutable import plan. It requires at least one supported assigned, merchant-managed or third-party fulfillment-order read/write scope. Each original grant category is recorded in the plan; loss of any category requires reauthorization even if another remains. Marketplace-only grants are not supported by this adapter.

The source resources are [FulfillmentOrder](https://shopify.dev/docs/api/admin-graphql/latest/objects/FulfillmentOrder) and [FulfillmentOrderLineItem](https://shopify.dev/docs/api/admin-graphql/latest/objects/FulfillmentOrderLineItem), reviewed with the documentation displaying 2026-10. Live account/query verification remains blocked by unavailable authorized access. An assignment says where fulfillment is intended; it does not establish a physical stock reservation or a merchant priority policy.

Each fulfillment-order line has a stable keyed connection identity. The group updatedAt supplies its observation revision; changed content at the same revision conflicts rather than replacing the old claim. Remaining quantity must be an exact nonnegative integer no greater than total quantity. Physical shipping, inventory-item identity and assigned location are required; nonshipping lines are excluded. Closed/cancelled groups and zero remaining quantity are released assignments, without inferred stock movement. Other supported group states are active assignment plans. Negative/contradictory quantities, missing required links, future timestamps and unfinished pagination invalidate the order cohort and enter review.

Records use basis derived_plan and remain on the source/fact tracks under records-v3. Existing observed_reservation inputs retain their reservation track. No assignment creates stock, reserves stock, changes provider available quantity, or establishes a new promise. Questions-v9 distinguishes cancel_assignment from release_reservation. Planning and reservation variance count only explicit observed reservations.

One bounded order object atomically commits the assignment records and a coverage member list. Each assignment carries its stable snapshot scope. Rust builds a bounded per-source/scope cohort index and includes only members of the latest supplied cohort; omitted/moved identities do not linger in current business answers. Old journal records and fixed recorded/effective cutoffs remain available. Missing cohorts create an explicit gap. Empty accessible cohorts do not prove there are no reservations elsewhere. Coverage always states reservation_basis missing and accessible_subset_only; an explicit supplemental reservation producer remains necessary for complete reservation answers.

Bounds: 10 orders/page, 10,000 outer pages, 200 fulfillment-order groups/order, 500 lines/group, 10,000 lines/outer page and 248 canonical shipping assignments/order. Exceeding any bound produces an error, never a truncated complete population. Repeated cursors and changed parent updatedAt during nested reads reject the page. HTTP responses are bounded to 2 MiB and each logical page to 45 seconds. Reads are not provider-atomic; updated-order polling cannot certify all changes to nested fulfillment orders. Six-hour reconciliation re-enumerates the selected accessible scope.

Strict from-now with older context declined discards the entire order's assignment quantities if any required older assignment is encountered. Raw retained evidence then contains only the minimal order header and decline marker. Retrying that marker cannot recover declined quantities or certify coverage. Invalid retained inputs use the existing bounded owner review retry; a still-invalid input remains unresolved. Credential, retention, rotation and independent-review limitations remain those of the shared source runtime.

Verification: `python3 scripts/verify-allocations.py --output .runtime/allocations-evidence.json` exercises synthetic HTTP, PostgreSQL, Rust, actual API/SDK MCP, EN/DE browser, strict context, scope loss, source replay, persisted cohort omission/move, two tenants, retained retry and process/deleted-projection recovery. This command is not live-provider or release validation.
