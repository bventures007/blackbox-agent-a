# Shopify inventory snapshots

The local source flow optionally imports inventory with the shop's inventory read grant. The pinned Admin GraphQL revision is 2026-10. This adapter is synthetic-tested; live account access, retention authorization and independent review remain unverified.

InventoryItem pagination traverses all accessible items, without using the item's updatedAt as a quantity cursor. InventoryLevel pagination includes inactive levels and all eight requested quantity states. A run is bounded to 100,000 items, 248 levels per item, 2 MiB per HTTP response and one 45-second page operation. Overflow, repeated cursors, schema changes or an item changing during nested pagination fail visibly. The importer never accepts a truncated location population as complete.

Each logical item commits its active location records and a snapshot cohort marker in one journal/outbox transaction. Rust selects only members of the current cohort for that connection and item. Thus a location absent from a subsequent fully enumerated snapshot does not linger in an aggregate, and no fabricated zero inventory or goods movement is needed. An invalid item snapshot publishes an explicit gap with an empty new cohort, preserving the old journal while preventing its values from masquerading as a valid new observation.

The authoritative basis is Shopify's supplied available quantity. Committed, reserved, damaged, quality-control and safety-stock amounts are retained but are not subtracted from available a second time. Incoming never fills current availability. Every quantity must have a timestamp at or before the fixed scan cutoff and a nonnegative integer value. Negative or missing values are quarantined, not clamped or replaced with zero. Shopify units here are pieces, not product shipping weight. Untracked items remain unresolved.

The source declares only a point snapshot for the individual item. No complete global stock population, historical opening balance, intermediate event history or cause of a stock adjustment is claimed. A multi-location read is not provider-atomic; that limitation is returned by API/MCP and displayed in English/German. Positive availability at the declared point uses the same business and effective cutoff. Asking at another millisecond or for a historical interval lacks coverage. Historical recorded cutoffs and effective times recover the old cohort. An opening-state opt-out excludes levels containing older quantity states, including strict from-now; the gap remains visible.

Existing account-bound encrypted credentials, per-page grant/account validation, lease fencing, immutable import plans, durable counters, bounded retries, scoped evidence and source health apply. New capabilities receive their own polling/reconciliation chain; subsequent jobs retain the most recent plan that includes that capability. Inventory scope loss stops collection and requires reconnect. Provider retry delays outside the supported seven-day scheduler bound become terminal failures rather than overflowing or being retried early. Owner retained-input retry uses the original encrypted item snapshot and cutoff, not newly fetched replacement data.

Reproduce with `pnpm test` and `python3 scripts/verify-stock.py --output .runtime/stock-evidence.json`. The latter uses actual synthetic HTTP, PostgreSQL, Rust, API, SDK MCP, EN/DE Chrome, process restart and deleted-projection recovery. It also checks location removal, duplicate scan replay, separate tenant identities/evidence, invalid current snapshots, strict opening consent and scope revocation. This is not distribution, performance or live-provider certification.

Official schema references reviewed: [InventoryItem](https://shopify.dev/docs/api/admin-graphql/latest/objects/InventoryItem), [InventoryLevel](https://shopify.dev/docs/api/admin-graphql/latest/objects/InventoryLevel), [InventoryQuantity](https://shopify.dev/docs/api/admin-graphql/latest/objects/InventoryQuantity), [inventoryItems](https://shopify.dev/docs/api/admin-graphql/latest/queries/inventoryItems). Exact field/event mapping is in integrations/mappings/shopify.stock.json.

Declined opening quantity values are excluded from retained raw evidence as well as canonical facts. Only minimal item/skip metadata remains. Untimed or malformed inputs cannot bypass that opt-out through the retry path.
