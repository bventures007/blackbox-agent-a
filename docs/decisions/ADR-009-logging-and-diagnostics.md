# ADR-009 Shared structured log record, bounded local files, outage CLI

**Status:** accepted 2026-10-31 (P0); validated by DIAG-01..08.

- One record schema (`packages/logging/schema.json`, `schema_version: 1`) is emitted by TypeScript (pino with a redaction/allowlist serializer) and Rust (`tracing` JSON layer mapped to the same fields). Fields: `schema_version, record_id, occurred_at, observed_at, level, event_name, message, component, service_version, instance_id, scope, tenant_id, connection_id, capability_id, run_id, operation_id, attempt, trace_id, span_id, parent_span_id, duration_ms, record_count, error_code, retryable, next_retry_at, action_code, journal_batch_id, committed_cursor, applied_cursor, truncated`. Unknown fields are dropped before emission; strings are clipped to 512 chars with control characters escaped; records above 16 KiB are truncated and flagged.
- Each component writes NDJSON to `/var/blackbox/logs/<component>/<UTC hour>.ndjson` on the shared `logs` volume through a bounded async buffer (drops counted in `diagnostics.dropped_records`). Container stdout receives the same records only for `WARN+` to avoid an unbounded duplicate; Compose `json-file` logging is capped (`max-size 5m, max-file 2`) and counted inside the 100 MiB budget.
- Retention: 7 days or 100 MiB total (configurable 1–30 days / 10–1000 MiB), enforced at startup, hourly and during ingestion when the cap is reached (oldest hour segments first). Debug level is enabled per component/connection for ≤15 minutes through a persisted `debug_windows` row that the logger re-reads every 5 s.
- Query path: the API scans hour segments newest-first within the requested time range with filters applied per record and stops at the page size; a per-hour sidecar index (`.idx.json`: counts per level/component/connection/run) prunes segments. This is bounded by the 100 MiB cap and measured in DIAG-07.
- CLI: `./blackbox logs|doctor|diagnostics export` read the same files from the host volume mount without the API/database.
