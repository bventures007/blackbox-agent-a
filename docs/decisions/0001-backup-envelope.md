# Backup envelope and bounded archive

Status: implementation in progress; not an operations acceptance result.

Use the maintained age 1.3.2 executable and standard age v1 file format with a native post-quantum hybrid recipient. Keep the independent recovery identity only in the protected host prompt/file-descriptor channel. Scheduled encryption needs only the public recipient. The pinned Mac ARM64 tools will be bundled in the installation archive; developer preparation downloads into this repository only, verifies the published archive SHA-256 and each selected member, and does not install global software. Linux AMD64 tools are a CI dependency, not a supported product distribution.

The [official release](https://github.com/FiloSottile/age/releases/tag/v1.3.2), [format specification](https://c2sp.org/age) and [versioned CLI documentation](https://github.com/FiloSottile/age/blob/v1.3.2/doc/age.1) define the dependency and format. Public-recipient encryption does not authenticate the sender or prove that a backup came from this installation. Restores therefore validate the encrypted manifest, installation identity, compatibility, file set and database invariants; the owner chooses the backup. A checksum detects corruption and is not a software-signing claim. No Sigsum verification is claimed by the current dependency preparer.

Stream a standard POSIX tar archive into age. Chunk a PostgreSQL custom dump into ordered 4-MiB tar members so no plaintext dump file is needed. Include coherent evidence, installation keys and policy state under the maintenance fence, then a final manifest containing member sizes/hashes and committed/applied cutoffs. The codec bounds individual ordinary members to 8 MiB, the manifest to 32 MiB, member count to 100,000 and plaintext archive content to 16 GiB. Exceeding a bound fails the generation; it never omits data or publishes partial success.

Restore validation is a full authenticated pass before writing a destination. A second pass uses the same opened ciphertext with integrity rechecks. Parse standard tar headers using Python's maintained TarInfo parser, rejecting links, traversal, duplicate names and extension headers before reading their bodies. No generic extract-all operation is used. Consume the final encrypted chunk and check the age process exit status, rather than assuming tar EOF proves authentication. Recovery keys accept exactly one native PQ identity; plugins, arbitrary paths, SSH and interactive passphrase forms are not loaded.

Unit proof covers actual pinned encryption/decryption, wrong recovery key, ciphertext mutation/truncation, manifest mismatch, duplicate members and unsafe tar metadata. This codec is not yet the complete database backup/restore workflow; maintenance, scheduler/retention, policy reconciliation, stale credential fencing and real recovery measurements follow.
