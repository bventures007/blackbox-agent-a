Installation guide · macOS Apple Silicon

From download to first answer

The package contains the ./blackbox wrapper, a pinned Compose configuration and the container images. You do not need Git, Node or Rust. You do need Docker Desktop.

Prerequisites: macOS 14 or newer on Apple Silicon (M1 or later), Docker Desktop 4.30 or newer running, about 3 GB free disk space. Network access is only needed for the sources you connect (for example Shopify) and for your own MCP client.

  1. Download and verify

    Download the archive from the landing page. Optionally compare the SHA-256 with the one shown there:

    shasum -a 256 ~/Downloads/blackbox-<version>-macos-arm64.tar.gz

    macOS may ask whether the download should be kept; a checksum match proves the bytes are intact. There is no signing or notarization in this pilot, and you never need to disable system security globally.

  2. Extract

    cd ~/Downloads && tar -xzf blackbox-<version>-macos-arm64.tar.gz && cd blackbox-<version>

  3. Check prerequisites

    ./blackbox doctor

    Exit code 0 means ready. Exit code 2 lists what is missing (for example a stopped Docker Desktop or a port already in use) with a code and the next step. Nothing is installed or changed by doctor.

  4. Set up and save your key

    ./blackbox setup

    Setup generates the installation secrets, loads the bundled images, starts PostgreSQL, applies migrations and creates your workspace. Your personal access key is printed once in the terminal — save it in your password manager now. It is never written to logs.

  5. Start and open

    ./blackbox up
open http://127.0.0.1:19080/

    Sign in with your key. Under Sources, connect Shopify (custom-app token) or run the synthetic example. Under Questions & Answers, ask one of the 24 questions. The UI defaults to English; switch to German with DE.

  6. Stop, restart, update

    ./blackbox down      # stop; journal, cursors and snapshots are kept
./blackbox up        # restart and catch up
./blackbox status    # services and port
./blackbox logs --since 1h --level warn   # works even while the API is down
./blackbox upgrade   # fenced, backed-up upgrade to a newer package extracted next to this one

    Closing the browser does not stop collection. Stopping Docker Desktop or shutting down the Mac stops processing; nothing is processed while stopped and nothing is lost. No autostart service is installed.

  7. Backup, restore, lost key

    ./blackbox backup --configure   # choose a destination and create the recovery key (shown once)
./blackbox backup               # encrypted generation
./blackbox restore FILE         # isolated restore; asks for the recovery key
./blackbox reset-access         # lost owner key: rotates it, keeps business data
Trouble? Setup phases are written to .local/setup.log in the extracted folder. ./blackbox doctor explains what to do next. For a tester report, export sanitized diagnostics from System & Diagnostics or with ./blackbox diagnostics export --output report.json and review the file before sharing — nothing is uploaded automatically.
