1. CURRENT PRODUCT SCOPE
Deliver a local Mac application: browser UI + persistent local backend, one automatically created workspace, one human owner and separate named read-only agent accesses. Installation, first import, trustworthy answers, restart and recovery are the first user-learning goals. No domain, email signup, passkey, external identity provider or central Blackbox service is required. The product is local; external providers and user-chosen agents may need internet access.

Required areas: independently servable landing page with prominent versioned Mac download and EN/DE installation guide; access-key sign-in/setup; recorder; Sources catalog/configuration/import progress/health; questions and evidence; Agent & MCP access settings; searchable/exportable history; local security, backup and owner-only System & Diagnostics with health, live/filterable retained logs, temporary debug and safe export. A workspace switcher, employee invitations, multi-owner UI, platform administration, public-server profile and remote client are out of current scope. Source cards must clearly distinguish implemented/configured/syncing/degraded/unsupported/planned. Shipping stays ordinary sources. Xentral remains absent. All business facts/claims need provenance and actual coverage.

The canonical journal, exact business logic, durable ingestion, Rust engine, tenant isolation foundation, all 24 positive/missing-data query contracts and complete authorized history access are retained. A local pilot must not become a static mock or a single unstructured file.

3. IDENTITY AND LOCAL SAFETY
Follow specs/IDENTITY-ACCESS-AND-RECOVERY.md. Explicit host setup creates the owner/workspace and a random personal access key with at least 256 bits of entropy. Display once through a protected local setup channel; save only its verifier. Browser key login issues a separate revocable HttpOnly session with optional remembered login. No first-public-visitor setup, default shared credential, secret in URL/localStorage, unauthenticated web reset or automatic key rotation on restart.

Support authenticated owner-key rotation and OS-authorized local reset without data loss. The login key is not the encryption key for business/provider data. Reset invalidates owner sessions and agent keys; restore fences stale access and requires rotation. Audit safe metadata only. Loopback access is authenticated; exact Origin/Host checks, CSRF defenses, throttling and safe sessions remain mandatory. Expose web/API on loopback only; keep PostgreSQL/engine internals private. Refuse unsupported public bind configuration.

Agent accesses have their own stable principal/key, workspace, read grant, status, last actual use, expiry and revoke action. The pilot grant reads all business records/evidence in the selected workspace, excluding secrets and administration. Never reuse the owner key for MCP or let a read-only agent ingest/write/configure sources. Implement current authorization through API, MCP, Rust, caches, cold reads and downloads. New requests fail immediately after durable revocation acknowledgment; streams/queued delivery stop within five seconds. No multi-replica auth infrastructure is needed.

Retain tenant IDs, scoped constraints/references, real RLS with non-owner/non-BYPASSRLS runtime roles, protected internal RPC and tenant-aware in-memory keys. Test at least two synthetic tenants, identical external IDs, pool reuse, unauthorized reads/writes and revoked keys. A single visible workspace must not create a global unscoped admin bypass. Employee roles, fine-grained dataset grants and public hosting security are future work.
